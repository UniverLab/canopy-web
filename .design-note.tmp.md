## FR1 — a missing registry folder is an empty catalogue

Facts: github.ts `errorFor` maps status 404/410 to `{kind:"not-found", status:404}`; every other failure is "rate-limit" or "upstream". `listOfficial` (official.ts:74-130) loops `["graph","node"]` and `return listing` on ANY ApiError.

Change, in `listOfficial` only:
- Replace `if (isApiError(listing)) { return listing; }` with: if `listing.kind === "not-found"` → `log("official: registry/<kind>s is absent; listing it as empty")` and continue the loop leaving `directories[kind] = []` (its initial value). Every other ApiError kind still `return listing` → callers keep answering the calm 503 busy page. Do NOT touch `officialStars` (a repo exists even without the folder; its errors already degrade to `stars: null`).
- No caller edits: pages/routes.ts `homeResponse`/`llmsResponse` and api.ts `case "official"` only check `isApiError(listing)`; with the change they receive `{graphs:[],nodes:[]}` and render the empty home / header-only llms.txt / 200 JSON automatically. Consequence to accept: llms.txt answers 200 with just its header line — absent registry = empty catalogue, same rule as the home.

Empty lines (exact wording is spec-mandated). Today `docList`/`docListMarkdown` (routes.ts:188-208) use `EMPTY_LIST` = "Nothing here yet." (copy.ts:46); that constant is rendered ONLY by the home Official lists (searchPage uses NO_RESULTS), so replace it:
- copy.ts: delete `EMPTY_LIST`; add
  `export const EMPTY_OFFICIAL_GRAPHS = "No official graphs published yet.";`
  `export const EMPTY_OFFICIAL_NODES = "No official nodes published yet.";`
  ("and the same for nodes" = the analogous nodes line, pinned here.)
- routes.ts: `docList(docs: Doc[], emptyLine: string)` and `docListMarkdown(docs: Doc[], emptyLine: string)`; the empty branches use `emptyLine`. `homePage` passes `docList(graphs, EMPTY_OFFICIAL_GRAPHS)`, `docList(nodes, EMPTY_OFFICIAL_NODES)` and the same for the markdown twin. Every other call site passes non-empty lists (searchPage short-circuits on empty), so no other site changes. Update the import list (drop EMPTY_LIST, add the two constants).

## FR2 — md.ts renders lists

Scope pin: `renderMarkdown` output contract for lists, inside the existing "safe by construction, no dependency" model. The block loop (md.ts:69-98) checks fence, heading, blank, paragraph. Insert list detection after the heading check, before blank. Module docstring (md.ts:3-11) gains "lists" in the supported set.

Line grammar (regexes, anchored):
- unordered: `/^(\s*)[-*]\s+(\S.*)$/`
- ordered:   `/^(\s*)\d+\.\s+(\S.*)$/`
- The `\S.*` requires non-empty text; "- " with nothing after stays a paragraph. Only spaces count as indent (a leading tab makes it not a list item). "as today" for emphasis means: emphasis is NOT rendered today (INLINE_RE is code+links only) and stays literal escaped text — do not add `*em*`/`_em_` support.

State and representation (pin exactly, keeps nesting trivial):
```
interface ListItem { text: string; child: ListBlock | null }
interface ListBlock { ordered: boolean; indent: number; items: ListItem[] }
```
plus `let openList: ListBlock | null = null` and a `flushList()` that renders and appends the block to `blocks` and clears it. `flushParagraph()` calls `flushList()` first; list-item detection calls `flushParagraph()` first (so a heading, fence or blank line always closes an open list).

Per list line with indent `i` and `ordered` flag:
- `openList === null` → open a block `{ordered, indent: i, items: [{text, child: null}]}`.
- `d = i - openList.indent`; `d >= 2` → nested: take `openList.items.at(-1)`; if its `child` is null, create `{ordered, indent: i, items: []}` as child; push `{text, child: null}` into that child. Deeper indents (4 spaces etc.) clamp into this one child — exactly one nesting level.
- `-1 <= d < 2` → sibling: push `{text, child: null}` onto `openList.items`. If `ordered` differs from `openList.ordered`, instead `flushList()` and open a new block (marker switch closes the list).
- `d < -1` → `flushList()` and re-parse the line fresh (its indent becomes the new base).

`flushList()` renders recursively: `<ol>`/`<ul>` (ordered flag), one `<li>` per item, item content = `renderInline(text)` (so links/inline code work inside items and HTML stays escaped), and a child block is emitted INSIDE the parent `<li>` right after the parent content, with no `<p>` wrapper. Source numbers are ignored; the browser numbers `<ol>`. A blank line or any non-list line ends the block (no lazy multi-line items, no lists continuing across blanks). FENCE check still wins before lists, so a fence line closes a list via flushParagraph. Blocks still join with `\n`.

No CSS/theme change: native ul/ol render fine in .readme; do NOT touch pages/theme.ts (would churn the big page-shell snapshots for no functional gain). Raw HTML remains escaped by construction (everything goes through renderInline/escapeHtml).

## FR3 — the e2e gate

package.json scripts: add exactly one line (keep the other scripts byte-identical; `test` must NOT grow the Playwright suites):
`"test:e2e": "npm run build && npm run test:remote-smoke && npm run test:remote-serve"`
placed after `test:remote-serve`. No new dependencies: @playwright/test 1.64.0 is already an exact-pinned devDependency, so the "two-week-old pin" guideline is satisfied trivially — add/bump nothing.

Playwright configs: in BOTH apps/remote/web/playwright.config.ts and apps/remote/web/playwright.serve.config.ts delete the line `channel: "chrome",` from `use:` so Playwright uses the bundled Chromium it installs. Keep `launchOptions.args` (["--no-sandbox","--disable-dev-shm-usage"]) — they are valid for bundled Chromium and needed on CI.

.github/workflows/ci.yml: append a fifth job mirroring the existing shape (do NOT touch the `on:` block — pull_request only, no push):
```yaml
  e2e:
    runs-on: ubuntu-latest
    needs: install
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run test:e2e
```

## FR4 — tests and how each requirement is verified

All unit tests follow the existing style: `describe`/`it`, fakeFetch Stub tables, REPO_DIR = "repos/UniverLab/canopy-web". Note fakeFetch answers 404 `{}` for any unstubbed URL (fakes.ts:95-96), so "registry/nodes missing" needs no stub unless the test wants it 200.

apps/graphs/test/official.test.ts — three new its in "the official listing":
1. "treats a missing registry folder as an empty catalogue": stubs `[{url: `${REPO_DIR}/contents/registry/graphs`, status: 404, body: {}}]` → result is not an ApiError (`expect("kind" in listing).toBe(false)`), `graphs` and `nodes` both `[]`. (nodes is an implicit 404 → covers both kinds in one case, plus it proves the loop continued past the first 404.)
2. "lists graphs while the nodes folder is missing": start from `STUBS(false)`, replace its nodes listing entry with `{url: `${REPO_DIR}/contents/registry/nodes`, status: 404, body: {}}` → graphs.length 1, nodes.length 0.
3. "keeps a 500 on the listing as a typed error": stub graphs listing `{status: 500, body: {}}` → `expect(error.kind).toBe("upstream")` (mirrors the existing rate-limit it at official.test.ts:102).

apps/graphs/test/pages.test.ts — in "data-layer failures":
1. "answers a missing registry folder with the empty official home, not the busy page": `call("/", {stubs: [{url: `${REPO_DIR}/contents/registry/graphs`, status: 404, body: {}}]})` → status 200, html contains EMPTY_OFFICIAL_GRAPHS and EMPTY_OFFICIAL_NODES, does NOT contain BUSY_HEADING. Plain toContain assertions — no new snapshot, so the existing pages.test.ts.snap must come out byte-identical (`git diff` on it empty).
2. "answers a 500 listing with the same calm 503": same shape as the existing rate-limit test but `{status: 500, body: {}}` → 503 + BUSY_BODY (this pins "do not remove the busy page").

apps/graphs/test/api.test.ts — one new it in "the JSON API": "answers /api/official with empty lists when the registry folders do not exist": stubs only the graphs 404 entry → 200, `body.graphs` and `body.nodes` are `[]`.

apps/graphs/test/md.test.ts (new, vitest under the same workers pool; NO node:fs — fixtures are inline consts, like pages-fixture.ts):
- ordered list "1. first\n2. second" → `<ol><li>first</li><li>second</li></ol>` (exact string).
- unordered, both markers: "- a\n- b" and "* a\n* b" → `<ul><li>a</li><li>b</li></ul>`.
- nested: "- outer\n  - inner" → `<ul><li>outer<ul><li>inner</li></ul></li></ul>`; and "1. one\n  - sub" → `<ol><li>one<ul><li>sub</li></ul></li></ol>`.
- marker switch: "- a\n1. b" → `<ul><li>a</li></ul>\n<ol><li>b</li></ol>`.
- mixed content: heading, paragraph, a list whose item carries inline code and a link, then a fence — assert the exact joined block string; links keep rel="nofollow", code stays `<code>`.
- sanitizer: "- <b>x</b>" → `<ul><li>&lt;b&gt;x&lt;/b&gt;</li></ul>`; a `javascript:` target in a list item degrades to its label text (SAFE_URL path).
- non-regressions pinned: "- " (no text) stays a paragraph; a fence line still interrupts a list; `escapeHtml`, `renderInline` exports unchanged.
- snapshot: new apps/graphs/test/md-fixture.ts exporting `QUALITY_BUBBLE_README` — the verbatim contents of registry/graphs/quality-bubble/README.md (copy the file; in the TS template literal escape every backtick, with a comment "verbatim copy of registry/graphs/quality-bubble/README.md"). Then `expect(renderMarkdown(QUALITY_BUBBLE_README)).toMatchSnapshot()` → commit the generated apps/graphs/test/__snapshots__/md.test.ts.snap.

Workflow YAML validity (FR4): locally run `python3 -c 'import yaml; yaml.safe_load(open(".github/workflows/ci.yml"))'` (PyYAML is present in the sandbox; verified). On the PR, Actions refuses to start any job if the file is malformed, so a parse error surfaces immediately; the job list must show `e2e` next to install/lint/typecheck/test/validate, with only `on: pull_request` at the top.

Verification order for the Implementer:
1. `npm run test:worker` (official + pages + api + md, snapshots create/update).
2. `npm run typecheck` then `npm run lint` (strict TS: the ListBlock interfaces are local to md.ts; no `any`).
3. `npm test` — the pre-existing suites must pass untouched (busy page, rate-limit 503, existing snapshots byte-identical).
4. `npm run build`.
5. `npm run test:e2e` (locally Chromium 1248 is already in ~/.cache/ms-playwright; only run `npx playwright install chromium` if launch fails with a missing-browser error).
6. YAML parse command above.
7. `git status` — only the 13 files listed at the top (11 edits + 2 new test files) plus the new .snap.

Out of scope, do not do: visual redesign, theme.ts CSS, remote app behaviour changes, adding Playwright suites to `npm test`, any push trigger, any new or bumped dependency, any change to github.ts error mapping or the busy() helper.
